## 1. 产品定位

**一句话**：帮求职者在投递前 1 小时内，从"无从下笔"到"产出一份能通过 ATS 初筛、经得起面试官追问的简历"。

**核心价值主张**：
- **写得出**：AI 生成个人简介、经历要点（STAR 化）、补齐履历空白 —— 解决"写作空白"。
- **排得好**：4 套组件化模板 + 实时分屏预览 + 一键 PDF/DOCX —— 解决"排版噩梦"。
- **过得了**：ATS 匹配度打分 + 缺词建议 + 语义级匹配诊断 —— 解决"初筛被机器筛掉"。
- **撑得住**：模拟面试（题目生成 / 答案评估 / 面试技巧）—— 解决"简历写出来的自己答不上"。

**边界（不做什么）**：不做简历代写中介、不做职位推荐、不做猎头对接。工具型产品，用户数据即用即走。

## 2. 问题定义与用户洞察

### 2.1 问题陈述
求职者（尤其应届生与转行者）在简历环节的平均痛点不是"没有经历"，而是：
1. **表达失能**：经历写得像流水账，量化意识和 STAR 结构缺失。
2. **排版耗时**：60% 以上的时间花在 Word 调格式，而不是打磨内容。
3. **机筛黑洞**：大公司 ATS 初筛淘汰率高，但用户投递前无从得知自己简历的"机器友好度"。
4. **虚假增强的诱惑**：用户会被"AI 帮你润色"引导到夸大甚至编造经历，投递后面试穿帮。

### 2.2 Persona（核心用户画像）

**P1 · 小林 — 应届生（主 persona）**
- 22 岁，双非本科，投秋招 60+ 家公司，简历改了 20 版依然收不到面试。
- 场景：投递前 1 小时对着空白模板发呆，不知道"社团经历怎么写成项目经历"。
- 诉求：快速产出 + 看起来专业 + 不心虚。

**P2 · 老张 — 转行者（次 persona）**
- 30 岁，从传统行业转互联网，经历与目标岗位 JD 关键词不匹配。
- 场景：拿到 JD 后不知道自己过往经历哪些可以迁移、怎么表述。
- 诉求：ATS 匹配诊断 + 缺词建议 + 把旧经历"翻译"成新领域语言。

**P3 · HR/面试官（对立面参照）**
- 诉求：简历真实、结构清晰、10 秒内抓到关键信息。
- 这决定了本产品的红线：**宁可产出平庸但真实的简历，也不产出漂亮但虚假的简历。**

| 维度 | Zety（海外） | 超级简历（国内） | Teal（海外） | **本产品** |

| 模拟面试 | 无 | 无 | 无 | **有（生成题目/评估答案）** |

| **JD 匹配 / 面试 历史记录** | ✅ v1.2 | 分析/练习结果自动入库，可回看、删除、重测；ATS 分数趋势图形成"改简历→分数提升"闭环 |
| **加密备份（AES-GCM）** | ✅ v1.2 | 密码即钥匙的本地导出/导入备份，缓解"清浏览器即丢"；为 v2.0 可选登录云同步预埋同一加密层 |

### Should have（二期）
- ATS 语义匹配诊断的人工抽样评估报告（自证打分质量）
- 简历导入的 OCR 能力（扫描件/图片型 PDF）
- ATS 历史"改后复测对比"报告（同 JD 两次打分的差分解读）

### Could have（三期）
- 可选云同步（opt-in，默认仍本地）
- 面试题库按 JD 定制深度生成
- 模板社区共创

### Won't have（本期明确不做）
- **上传自定义模板** —— 三条理由：① 与"排版必须 100% 确定性"红线冲突，用户上传模板的解析渲染结果不可控，崩坏成本由产品背；② 通用模板解析 = 做半个排版引擎，工程性价比极低；③ 花哨自定义排版恰恰是 ATS 初筛杀手，与核心卖点矛盾。真实诉求（"不想和别人撞版"）已由主题定制（主色调 × 字体）低成本满足。
- **强制注册 / 登录门槛** —— 不登录必须能完整使用全部核心功能。账号只作为 v2.0 的"可选增值"（跨设备云同步），且同步层采用端到端加密、服务器只存密文。这不是推翻隐私优先，而是把口径演进为"默认本地，登录可选"（见 §8 取舍 1 的修订）。
- 简历代写 / 人工服务 —— 破坏工具型产品边界
- 职位推荐 / 猎头对接 —— 资源投入大且偏离核心

**砍掉过什么**：最初设想做"简历诊断报告导出 PDF"和"多语言简历"，在 MVP 阶段砍掉 —— 前者用户在编辑器内即可看到全部诊断结果，导出是伪需求；后者优先服务中文求职主场景。

## 5. 用户旅程与核心漏斗

```
主路径：Landing ──→ Editor（进页）──→ 点 AI 生成 ──→ 生成成功 ──→ ATS 分析 ──→ 导出 PDF
                    editor_view      ai_generate_click  ai_generate_success  ats_analyze    pdf_export

冷启动加速路径（v1.1 新增）：
已有简历用户：Landing ──→ /import 上传 PDF/DOCX ──→ AI 结构化 ──→ 预填编辑器 ──→ （并入主路径）
                          resume_import(start/success/fail)
```

北极星指标：**成功导出 PDF 的会话数**（一个会话完成"写→改→测→投"全链路才计一次）。简历导入把漏斗入口的"空白起笔"改为"从 80 分起步"，直接攻击冷启动流失。

## 6. AI 能力边界与失败模式治理（核心章节）

### 6.1 能力边界划分原则
> **生成类交给 LLM，确定性类用代码。** AI 只做"语言生成与改写"，排版、打分、导出全部用确定性方案，保证可复现、可兜底。

| 环节 | 方案 | 为什么不用 AI |
|---|---|---|
| 排版 | React 组件化模板 | 排版必须是 100% 可预测的，AI 生成 CSS 会随机崩坏 |
| 导出 | html2canvas + jsPDF | 确定性渲染，所见即所得 |
| ATS 打分 | 关键词匹配 + 语义模型 | 打分需可解释、可复现，用于展示给用户的数字不能有随机性 |
| 内容生成 | GPT-4 + JSON Schema | 这是 LLM 真正擅长的事 |
| 简历导入结构化 | GPT-4 JSON mode（temperature 0.1）+ Zod 强校验 | 自由文本→结构化是 LLM 强项；但输出必须过 Zod 校验才交给前端，不合格直接报错不降级放行 |

### 6.2 AI 失败模式与兜底清单

| # | 失败模式 | 触发场景 | 兜底机制 | 状态 |
|---|---|---|---|---|
| F1 | **输出格式不合法**：模型返回非 JSON 或缺字段 | 任何生成请求 | Prompt 强制 JSON Schema + 服务端 Zod 校验；校验失败返回结构化错误，前端展示可读错误信息而非白屏 | ✅ |
| F2 | **建议编造事实**：AI 给出的"优化建议"暗示用户编造经历/技能 | 简历摘要、要点生成 | **建议真实性校验模块（verify-suggestions）**：对建议逐条检查是否有简历原文依据，无依据的建议被标记/过滤；ATS 页同步展示校验通过率 | ✅ |
| F3 | **幻觉补空**：用户"补履历空白"时 AI 编造公司/项目 | 补空白功能 | 只生成"表述框架与追问清单"，明确标注需要用户自己填入事实；不直接产出可冒充真实经历的内容 | ✅ |
| F4 | **API 超时/限流** | 高峰期 | 服务端限流（express-rate-limit）+ 前端 loading 态 + 失败事件埋点（ai_generate_fail）用于发现异常率 | ✅ |
| F5 | **超长输入**：用户粘贴超大段 JD/经历 | ATS 分析 | 输入长度前置校验与截断提示 | ✅ |
| F6 | **生成内容跑题/质量差** | 任何生成请求 | 双通道质量信号：① 用户可手动改写（编辑器不锁定）；② 埋点记录生成耗时与失败率，作为 prompt 迭代依据 | ✅ |
| F7 | **匹配分被误读为"录用概率"** | ATS 页 | 产品文案明确"匹配分反映 JD 关键词与语义覆盖度，不代表录用结果" | ✅ |
| F8 | **导入文件不可解析**：扫描件/图片型 PDF、加密文档、旧版 .doc | 简历导入 | 双层拦截：① 提取文本 < 30 字符 → 422 + 可读原因（"可能是扫描件，请先转可编辑文档"）；② LLM 输出 Zod 校验不过 → 502 提示重试，绝不把残缺数据写入编辑器；③ Prompt 明令"禁止编造原文不存在的信息"，缺失字段留空并在前端给出核对清单（warnings） | ✅ |

### 6.3 AI 伦理红线
1. 不主动建议用户添加其简历中不存在的技能/经历。
2. 所有 AI 产出内容用户可逐字修改 —— AI 是"初稿作者"，用户是"署名作者"。
3. 不使用用户简历数据训练模型（因为根本不上传，见 §7）。

## 7. 数据与埋点（v1.0 新增）

### 7.1 隐私原则（架构级承诺）
- **零上传**：埋点数据只存于浏览器 localStorage（`arb_analytics_events_v1`），没有任何网络请求。
- **设备假 ID**：`arb_device_id` 为随机 UUID，与任何真实身份信息无关联，不上传。
- **无 PII**：事件属性只含页面路径、功能名、状态码、耗时、分数等聚合维度，**不含简历任何文本内容**。
- **用户完全掌控**：数据看板页可随时**一键清空**全部事件、**导出 JSON** 自查。
- **限容自愈**：单机事件上限 1500 条，FIFO 自动淘汰，不会撑爆存储。

### 7.2 事件规范（与代码实现一一对应）

| 事件名 | 触发时机 | 关键属性 | 漏斗意义 |
|---|---|---|---|
| `page_view` | 路由切换 | `page`, `referrer` | 流量分布、页面级留存 |
| `ai_generate_click` | 点击任一 AI 生成按钮 | `feature: summary/bullets/star` | AI 功能触达 |
| `ai_generate_success` | 生成成功 | `feature`, `ms`（耗时） | AI 可用性 & 性能 |
| `ai_generate_fail` | 生成失败 | `feature`, `reason`（截断 120 字） | 失败模式 F4 监控 |
| `ats_analyze` | ATS 分析完成 | `score`（匹配分） | 核心价值功能使用度 + 分数分布 |
| `ats_verify` | 建议真实性校验完成 | 通过率相关字段 | AI 诚实性护栏运行证据 |
| `pdf_export` | PDF 导出成功/失败 | `status: success/fail` | **北极星指标的直接观测点** |
| `docx_export` | DOCX 导出成功/失败 | `status`, `ms` | Word 格式需求覆盖度 |
| `txt_export` | 纯文本导出成功/失败 | `status` | 备用导出路径 |
| `resume_import` | 简历导入开始/成功/失败 | `status`, `fileType: pdf/docx`, `warnings`(成功时), `reason`(失败时), `ms` | 冷启动加速路径转化率 |
| `theme_change` | 用户修改主色调/字体 | `kind: accent/font`, `value` | 个性化需求强度（支撑"要不要做更多模板"的决策） |
| `resume_version_switch` / `resume_version_create` / `resume_version_delete` | 多版本操作 | `action` 等 | 多版本功能使用率（"投多家公司"场景验证） |
| `ats_history_save` | ATS 结果自动入库 | `score` | 历史/趋势数据有效性 |
| `interview_history_save` | 面试练习保存 | `questions` | 面试模块完成率 |
| `backup_export` / `backup_import` | 加密/明文备份操作 | `encrypted` | 备份功能使用率（支撑"要不要做云同步"决策） |

### 7.3 核心看板（`/analytics` 页面）
- **漏斗转化视图**：page_view → ai_generate_click → ai_generate_success → ats_analyze → pdf_export
- **AI 功能健康度**：三功能（摘要/要点/STAR）的成功率与平均耗时
- **ATS 分数分布**：用户简历匹配分的分布，验证"改前 vs 改后"提升故事
- **原始事件流** + 导出 JSON + 清空数据

### 7.4 已知局限（诚实声明）
本地埋点无法统计**留存与回访**（清浏览器数据即丢失）、无法跨设备归因、样本即用户本人/其分享对象。这套埋点的价值在于：① 验证漏斗模型与事件设计（换 ANY 上报后端即可复用）；② 支撑产品决策的完整方法论展示。这是有意的产品决策，不是能力缺陷（见 §8）。

## 8. 关键产品取舍（面试追问预案）

**取舍 1：隐私优先 vs 数据飞轮（v1.2 修订：从"纯本地"演进为"默认本地 + 可选登录"）**
- 选择：数据默认只存本地，不登录完整可用；登录作为 **v2.0 可选增值**（跨设备云同步），采用端到端加密、服务器只存密文。
- 收益：隐私零焦虑 → 信任 → 转化；不设登录门槛，冷启动不被"注册墙"劝退；加密同步层同时是"持久化丢失"问题的解法。
- 代价：无账号阶段无留存运营、无跨设备、无法做 A/B；加密云同步需自研密钥管理，且"密码即钥匙、忘了不可找回"要向用户说清。
- 决策依据：不做"强制账号"（拒绝注册墙），也不做"永不登录"（回避真实需求），选中间态并公开取舍 —— 这是 v1.2 产品决策的核心。

**取舍 2：全功能免费 vs 商业化**
- 选择：MVP 全免费。
- 逻辑：0→1 阶段优先验证价值假设，付费墙会把样本量打到无法验证。商业模式留待 PMF 后（模板高级款、批量导出、团队版）。

**取舍 3：AI 生成排版 vs 模板化**
- 选择：模板组件化。
- 逻辑：简历排版的目标是"专业且正确"，不是"新颖"。确定性方案的失败率是 0，AI 生成的失败率不可接受（F1 同源逻辑）。

## 9. 路线图
