## 🔍 测试中发现并修复的 Bug

**问题:AI 导入/生成返回 401(Token is invalid)**

- 现象:导入接口报 `AuthenticationError: 401`,`www-authenticate: Bearer realm="siliconflow"`
- 根因:这台电脑的系统环境变量里预设了 `OPENAI_BASE_URL=https://api.siliconflow.cn/v1`;而 `server/.env` 用的是 **DeepSeek**(`api.deepseek.com` + deepseek-chat key)。代码里 `dotenv.config()` 默认**不覆盖已存在的环境变量**,于是运行时 baseURL 用了 siliconflow、key 用了 DeepSeek,牛头不对马嘴 → 401。
- 修复:`server/src/services/openaiClient.js` 改为 `dotenv.config({ override: true })` —— 本地有 .env 就以 .env 为准;云端(Render)没有 .env 文件,dotenv 不写入任何值,平台注入的环境变量照常生效,不会影响部署。
- 修复后验证:直接 `npm run dev`(不注入任何环境变量)再次导入同一 PDF,成功返回李奕聆的完整结构化数据。

## ⚠️ 需要你留意的点(非 Bug)

1. **DOCX 那版简历没写"目标职位"**,导入后该字段为空,进编辑器补一下即可(数据本身没问题)。
2. 导入结果会**覆盖当前激活的简历版本**(设计如此),测试时若在浏览器里导入了,之前版本会被覆盖,可用编辑器版本条/个人中心恢复。
3. 「导出 PDF」主链路在浏览器端(html2canvas + jsPDF),无法用命令行完整模拟,建议你在页面上点一次「下载 PDF」肉眼确认版式。
